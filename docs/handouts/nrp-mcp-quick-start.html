1

Sign in to Nautilus 2 min

Go to nrp.ai, click Login, choose University of California, Riverside, and accept the policy. Your first sign-in is what activates your namespace invite.

You see your name on nrp.ai; your namespace admin sees you.
2

Install nrp-mcp 2 min

Mac / Linux$ curl -fsSL https://raw.githubusercontent.com/UCR-Research-Computing/nrp-mcp/main/scripts/install.sh | sh $ echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc # macOS; Linux: ~/.bashrc $ export PATH="$HOME/.local/bin:$PATH" WindowsDownload the windows_amd64.zip from the Releases page, then paste the PowerShell lines from the web version (KB031, QR on the back). They put nrp-mcp.exe on your PATH.
nrp-mcp version prints 0.7.0 or newer.
3

Connect your laptop 8 min

Download your config at nrp.ai/config (it lands in Downloads), then run:

$ nrp-mcp setup

It installs kubectl and the sign-in plugin into your user folder (no admin rights, checksums verified), puts the config in place, then opens a normal browser tab for the UCR sign-in. It asks before changing anything.

It ends with “This computer is ready for Nautilus.”
4

Install Hermes Agent and add your key 8 minrecommended

Mac / Linux$ curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash WindowsPS> iex (irm https://hermes-agent.nousresearch.com/install.ps1)

Open a new terminal. Store your Gemini API key and pick the model:

$ hermes config set GEMINI_API_KEY your-key $ hermes config set model.provider gemini $ hermes config set model.default gemini-3.8-flash
hermes chat -q "hello" answers.
5

Give Hermes the nrp tools 2 min

$ hermes mcp add nrp --command "$HOME/.local/bin/nrp-mcp" --args serve

Windows: --command "$env:LOCALAPPDATA\Programs\nrp-mcp\bin\nrp-mcp.exe". Answer Y to enable all 9 tools; if it cannot connect, answer N to “save anyway” and fix the path. Then start hermes and ask:

Where do I stand on Nautilus?

It answers with your user, namespace, what is running and your GPU quota.
Your key is yours. Never paste it into a chat, a repo, a shared doc or a screenshot. Turn over: the exercise, what to say, the rules
Hands-on · Slurm to Kubernetes

Move a Slurm array job to Nautilus in two sentences

The exercise

Get examples/slurm-array-bootstrap from the project (QR below, Code, Download ZIP): an R bootstrap of a trimmed mean and a normal Slurm script with --array=0-9. In that folder, ask Hermes:

  1. Plan the Slurm script in this folder and show me what each line becomes.
  2. Run it.
  3. How did it go?
  4. Clean up everything I made.
Slurm lineBecomes on Nautilus
--cpus-per-task=1
--mem=2G		CPU and memory request; limits equal requests
--time=00:20:00a time limit on the Job (whole hours)
--array=0-9an Indexed Job: 10 tasks, each with its own $SLURM_ARRAY_TASK_ID
module load Ra container image with R in it

Ten tasks, ten seeds, ten different answers, in about a minute. The same script still runs on Slurm.

Rules of the road

  • P1 data only. Public, non-sensitive data. No student records, PII, clinical or controlled data.
  • No idle GPUs. Ask for a GPU only when the code uses one; idle GPUs get accounts suspended.
  • Nothing public without asking RC. Publishing a web app needs you to type its URL back.
  • Clean up when you finish. Jobs left running hold resources others need.
  • Keys stay private. Never paste a key into a chat, a repo, a shared doc or a screenshot.
